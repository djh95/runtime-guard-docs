# 词汇表（用户面）

> **入口页。** 读案例 / 启服 / 定界时碰到自造词，先查这里。  
> keep-set 索引与结案四档政策仍见 [README.md](./README.md)；Agent 细则见 [`06_agent_skills`](../06_agent_skills/README.md)。  
> **不要**再用 GAP / FAIL+GAP / PASS·FAIL 当案例 **headline 结案**——结案只用四档；检测用「检出 / 漏检 / 乱码漏检」。

---

## 第一类：自造词（须在入口可见）

| 词汇 | 含义 |
|------|------|
| **GAP / FAIL+GAP** | **退役结案标签**（历史·检测侧）。旧文：异常已复现（有 trigger/precision），但 detector **漏检**（detect=0）→ 记 detector gap。现 keep-set **禁止**当案例总评；改写 **结案四档** + 检测「**乱码漏检** / 漏检」。skills 验 detector 的机读标签另说，不进案例标题。 |
| **soft-inv / soft-inverse** | 按上游**修复 PR 做反向注入**，构造同类故障供教学/评测（soft-inverse）。不是现网必现 bug 本身；过量矩阵刷分（ones/zeros/abs…）已停。 |
| **keep-set** | 本仓对外保留的**典型异常场景集**（当前约 **15** 个 `cases/Sxx/`）。完整跑批矩阵在内部评测仓，不在本目录。 |
| **清洁标杆 / 标杆 / ref** | **未打 overlay、未注入异常**的对照服务（或其对账用的 KV dump）。抓标杆时应用同一段 **token ids**（见 force-feed）。 |
| **buggy vs ref** | **异常侧**（打了 overlay / 出坏输出的请求及其 KV）**对照**清洁标杆侧，做 shape / 数值 / 余弦对账。 |
| **force-feed** | 把报告里的 **token id 原样喂给**干净服务（禁止把 prompt 字符串再 tokenize）。用于同序列抓标杆 KV。 |
| **首分歧** | buggy 与 ref 对比时，**第一个**出现 KV 问题（数值问题，或余弦明显不对）的 token/层位置。表2 画的是「首个出问题的 token」，不是窗内 token0 默认值。 |
| **Q1–Q5 → 十问** | 旧定界曾用 **Q1–Q5** 短清单。现行用户面检查单是 **[02 §5 十问](../02_problem_localization/README.md#5-kv-定界十问检查单有-buggyref-时按序)**（异常→prompt/output→层→粒度→恢复→out0→形态→仅 PD→特性→对照完整性）。文中若仍写 Q1–Q5，视为旧编号，含义并入十问。 |
| **identical-mode / unique-mode** | 离线**评分口径**：identical = 多条请求输出是否**彼此内容相同**；unique = 按「各请求各不相同的乱码/垃圾」计。identical-mode 会**低估**「每条都乱但互不相同」的 precision（如部分 S45）；**仍以 detect / samples 为准**，三层要拆开读。 |
| **canonical（栈/树）** | **干净产品代码树**（未当场景改写的 vLLM / vllm-ascend 工作树）。异常只许叠 **overlay**，禁止直接改 canonical 冒充场景。 |
| **builder / builder 机** | 负责**起服、打 overlay、写失败证据（FE）、重跑复现**的角色/机器（实验室常称 builder 机）。与只跑离线 skills/verify 的「skills 机」分工不同。 |
| **挖矿 / PR-rooted mining** | 从真实 **bug 修复 PR** 反推可复现异常场景：一 PR → 一类根因（typed），同类勿堆太多；优先 both / ascend-only。 |
| **爬山（skills 爬山）** | skills / 定界能力按版本**迭代验证**（分析缺口 → 改 skill → 同证据重验 → 记前后）。不是调参刷分。 |
| **G2 / Guard pin** | 实验**钉死的 Runtime Guard / 产品树 git 提交**（例 G2 ≈ A+#18644，`f2aefd068…`；跑批里常作 `wt_sha`）。不是硬件 pin；用来保证案例间数字可比。 |
| **10-gate** | 异常评测里约 **十个门禁场景**构成的主门集（origin-faithful 可跑通的核心集）。**不是** KV 定界「十问」。`synthetic/` 阳性对照**不算** 10-gate PASS。 |
| **有限垃圾 / garbled / finite garbage** | **logits 仍有限**（无 NaN/Inf）但语义已是乱码/垃圾的输出。`logits_finite` **抓不到**这类；用户面优先说 **「logits 有限乱码」**（或「乱码漏检」），少用含糊的「输出有限」。 |

## 第二类：别处有定义，入口须挂链/短注

| 词汇 | 含义 | 详见 |
|------|------|------|
| **三层率（trigger / precision / detect）** | **trigger**＝注入路径打中次数；**precision**＝输出被判/见异常次数（≠模型精度）；**detect**＝Guard 报告命中次数。三者不相等，须分列。 | 本表；案例 `三层计数.json`；[03 检测](../03_detectors/README.md) |
| **origin-faithful** | **复现纪律**：overlay 走与原 bug **同一逻辑**；禁止 NaN 强写、token fill 等伪造症状。≠ 表格字段 **Origin**（代码树标签）。 | [`build-anomaly-env`](../06_agent_skills/build-anomaly-env/SKILL.md) |
| **overlay** | ① **异常 overlay**：`evidence/overlay.patch`，叠在 canonical 上制造故障。② **启动 overlay**：`01` 里 `runtime_config` 字典，合并进默认配置后写盘——**不是**打故障补丁。 | [01 启服](../01_enable_and_start/README.md)；案例 `overlay.patch` |
| **amplifier / amplified-only** | **伪造症状的放大器**（强写 NaN、fill 复读 token、改计算发明坏输出）。**仅靠放大器跑通 ≠ PASS**；amplified-only 旧结论作废。抬复现率只用合法 knobs（并发/util/长度等）。 | [`build-anomaly-env`](../06_agent_skills/build-anomaly-env/SKILL.md) |
| **repro_mode（四态）** | 规格字段，这一跑怎么打出异常：`origin`（忠于原逻辑、未特调负载）· `origin_tuned`（同逻辑 + **合法 knobs** 抬复现率；本 keep-set 常见）· `blocked`（环境挡死）· `hard_defer`（太难/无安全 knobs，先放下继续挖）。 | 案例 `规格说明.md`；协议同源 PRINCIPLES |
| **A / B / C（PR-weighted）** | 评测语料切片：**A**＝挂真实修复 PR 的类；**B**＝非冗余的类型代表；**C**＝soft-inv 矩阵冗余（刷分密度）。谈 Guard 实力用 **A∪B**；**C 不进头条**。 | [`_internal` 评估摘记](../_internal/guard-skills-evaluation-20261018.md)（过程文档） |

## 与 keep-set 强相关的短注（交叉）

| 说法 | 一句话 |
|------|--------|
| **结案四档** | 未复现 / 复现未抓到 / KV 一致→排除 KV / KV 不一致→定界。见 [README · 结案四档](./README.md#结案四档主标签)。 |
| **检测（辅）** | 检出 / 漏检 / 乱码漏检 / 无可检（非漏检）+ 三层数字；**不是**结案总评。 |
| **Origin（字段）** | `vllm-only` \| `ascend-only` \| `both`：异常逻辑落在哪棵树。≠ origin-faithful。 |
| **FE** | 失败证据包（fail-evidence）：samples / reports / 状态摘要等。 |
| **manual_dump** | detector 未亮（detect=0）时仍可手动抓异常 KV；漏检 ≠ 无异常 KV。 |
